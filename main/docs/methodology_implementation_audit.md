## Regressions and minimal corrections

Before production edits, the initial17-method defect regression run produced26 failing subtests and3 errors. These include the absent NaN-marker interface and missing-series KeyError, not numerical acceptance relaxation. The independent twin scalar fixture failed all five rounds by1.4901161e-8 before the lead approved correction. Separate stale-manifest and wrong-null-identity regressions each failed because no ValueError was raised. These failures are retained as local logs outside the checkout; raw logs/results are not committed.

Corrections live in the focused `tests/test_exp12_methodology_corrections.py` (22 methods). Existing PC end-to-end assertions are strengthened to require test-only forced reports to STOP with no chosen m; arithmetic/sensitivity checks remain. Existing GPU callers explicitly identify only `train/actor_grad_cosine`'s scheduled NaN marker; model leaves remain strict. No tests or failing scientific gates were removed or weakened. After the literal L correction, the old twin probe test no longer detected a Q1-only **aggregate P** mutation. A focused pre-fix mutation run demonstrated this coverage gap. The existing test is strengthened to independently assert mean P, and the break harness adds a separate difference-of-means versus mean-of-paired-losses mutation (73 total, preserving all72 earlier mutations). The first full break run also exposed fixture masking: an existing-manifest refusal satisfied the generic ValueError assertion even when relative checkpoint paths were incorrectly accepted. The negative path test now runs in a separate fresh directory and checks the absolute-path error. This strengthens the original invariant without altering scheduler behavior.

The common `paired_loss` function is used by longitudinal probes, ancillary Check2 L reporting and certification. It leaves the single-critic expression unchanged and preserves twin fitting and P aggregation. The approved mean-score Check2 comparison is intentionally a separate expression. The common range function rejects missing, duplicated or nonfinite configured evidence. It retains the superseded rule as informational evidence only.

Input safeguards do not repair old measurements. Legacy null JSONL without matching config/revision/recorded-backend provenance is preserved and refused for provenance-checked resumption. The recorded runtime fields are JAX/backend/CUDA/device/precision; this is not a complete dependency or launch-environment freeze. Retain pinned package versions and XLA launch flags as additional evidence before qualification. Dirty/unknown-source resumption is refused. Valid matching data can resume. Manifest generation now requires a fresh output directory, leaving old parent/arm command files untouched. Replay preflight reads NPY headers, not a duplicate full replay allocation; full payload restoration still uses the same arrays/order/state assignments. Runtime LATEST and offline certification reject empty, escaped, missing or symlink-escaped state directories. A separate failing fixture demonstrated that the offline pointer accepted `..` when its parent held placeholder payload files; the offline guard was aligned with the runtime confinement rule. Valid fixture/real-state behavior is rerun below.

## Campaign census and omission analysis

The independent CPU reference/census script reconstructs all195 commands, composes **every seed's** config, and compares the Cartesian product against separately stated approved architecture/environment/seed sets. All195 unique parents,39 architecture/environment settings and130 scaled eligibility candidates are present. It checks budgets, checkpointN/20 cadence, actor shape, critic count, UTD/repeat, probe/trigger settings, continuation/evaluation horizon, optimizer settings and absence of forced triggers/frozen m. No arm command is generated before an eligible completed fork and frozen m. Existing manifest tests additionally check unique checkpoint/log paths and GPU-device grouping.

Potential omissions are distinguished from accepted results:

- Scheduler `classify_exp12` treats any DONE marker as done without full scientific certification. A stale/corrupt DONE could suppress rescheduling. Confirmatory validation independently requires all195/130 source-complete entries and rejects the missing/invalid result; it cannot silently reduce the study. Preserve evidence and investigate before removing markers. No automatic rerun/deletion is added.
- Arm generation consumes FORK_READY/device metadata; its lightweight discovery is not a full tensor/state certificate. Runtime checks source-config/device restoration; final analysis recomputes eligibility and requires every eligible fork's complete two-arm evidence. An invalid fork causes failure rather than a legitimate null.
- Device grouping is by slug; grouping does not enforce the whole-study one-model constraint by itself. Frozen study and runtime validation enforce exact model/runtime expectations. Submit only the approved single-model population after qualification.
- Raw progress loaders and direct low-level plotting functions can show partial observations. Only the default confirmatory entry points enforce full validation and publish a certificate; `--exploratory` explicitly labels uncertified output. Missing runs are not valid no-trigger outcomes.
- Source/checkpoint certification checks presence, metadata consistency and referenced evidence, but does **not** fully decode every Orbax tensor or checksum every replay payload in offline analysis. Runtime restore and complete-state comparisons provide stronger evidence for actually restored checkpoints. The new replay header/pointer guards detect structural corruption; they are not a universal bit-rot certificate.
- No available production results were claimed complete. The195-command census is configuration validation, not completion of195 runs.
