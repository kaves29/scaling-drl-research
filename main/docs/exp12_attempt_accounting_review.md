## Review conclusion

The old comparator counted attempt directories instead of selecting a validated
successful process. A failed warm attempt plus a successful warm attempt therefore
forced INCOMPLETE despite empty bitwise differences. The new comparator permits
that history, but selects exactly one expected-exit attempt per stage. The
expected crash exit remains 3; other accepted exits remain 0. It does not select
by newest timestamp, largest job ID, or best numerical result.

Every preserved directory must have a valid stage/numeric Slurm job identity,
process record, consistent exit status, original source commit, exact submitted
specification, and checksum manifest. Job IDs cannot be reused across stages.
Missing or malformed failed-attempt evidence also prevents PASS. Accepted attempts
additionally require dependency, GPU inventory and workload logs. Their manifests
bind the current stage receipt and all current stage artifacts, including deleted
files named in the manifest. Receipt stage, source and canonical specification
hash must agree. Multiple expected-exit attempts are ambiguous and rejected.

Earlier failed manifests describe a historical global tree: a later successful
attempt legitimately replaces the shared warm-stage receipt. The comparator
checks each failed attempt's own preserved files against that attempt's manifest;
it does not demand that historical hashes of subsequently replaced global files
match the later successful tree. These historical checksum records remain intact.
Each accepted attempt must bind its own stage's **current** files. The report lists
all validated failures and the accepted job/receipt/manifest hashes explicitly.

This is integrity/consistency verification, not cryptographic authentication of
Slurm. A party rewriting all payloads and manifests could forge a consistent
archive; independently archived checksums and scheduler records remain the trust
anchors. No external scheduler access is attempted.

The GPU workload, scientific invariant checks, precision/placement checks, cache
observation and verdict classifier are AST-identical to the baseline. Checkpoint
counter validation and all four existing bitwise comparisons remain in place.
No training, configuration, timeout, threshold or numerical tolerance changes.
